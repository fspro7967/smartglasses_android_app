# 朗读期间不屏蔽上行音频

应用在朗读回复的同时,仍然把设备上行的麦克风音频照常送进识别。开发板的喇叭和麦克风在同一块
板上,所以念出来的声音理论上会被拾到、被识别、再触发一次新的提问。2026-11-11 通读代码时提出了
这一点,所有者决定**不处理**。

## 考虑过的选项

- **手机侧屏蔽**:朗读期间丢弃上行音频。实现最简单,代价是使用者无法在助手说话时插话。
- **固件侧屏蔽**:播放期间暂停上行(固件已支持 `mic:off` / `mic:auto` 指令)。
- **不处理**(选定)。

## 后果

- 这个回环**只是从代码推断出来的,没有在真机上观察过**。实际会不会发生,取决于喇叭音量、
  麦克风朝向,以及被按英文识别的中文语音(见 `0002-english-in-chinese-out.md`)会不会产生
  非空的转写。
- 如果真机上出现「它在自己跟自己说话」,原因就在这里,不必从头排查。
- 与 `0006-queue-overlapping-replies.md` 叠加:自问自答产生的回复同样会排进朗读队列。
