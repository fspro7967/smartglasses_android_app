# 仓库里的签名密钥是有意公开的测试密钥

`android_release.keystore` 和带有其口令的 `.vscode/settings.json` 都被 git 跟踪,而且这个仓库
曾经是公开的,所以这把密钥应当视为已经公开。2026-11-11 所有者决定**接受现状**:把它认定为一把
测试/演示用的签名密钥,不轮换、不重写历史,只把 README 和 `.gitignore` 里「它们不在版本库里」
的说法改成与事实一致。

## 考虑过的选项

- **轮换**:生成新 keystore,把两个文件移出版本库。历史里仍有旧密钥,已安装的包必须卸载重装。
- **轮换并重写历史**:再用 `git filter-repo` 清掉历史并强推。所有协作者要重新克隆。
- **接受现状**(选定):零成本,克隆下来就能出 Release 包,升级兼容性不断。

## 后果

- 用这把密钥签出来的包**不具备任何来源保证**——任何人都能签出同样签名的包。
  它可以用于自己试用和演示,不能用于对外分发。
- 哪天需要正式发布,必须另外生成一把只留在版本库之外的密钥;届时用户要卸载重装一次。
  `.vscode/settings.example.json` 是为那一天准备的脱敏模板。
- 同样因为这个认定,签名口令经命令行传给 `apksigner`、会进构建日志这件事暂时不算问题
  (`.scratch/repo-hygiene/issues/08`);换用正式密钥时要重新考虑。
