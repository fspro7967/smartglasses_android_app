## 判据

1. **首屏不被模型加载挡住**(`issues/05`):冷启动后界面立即可操作;几秒后状态栏出现
   「Whisper 模型加载成功！」。在此之前「选音频」按钮是灰的;若此时已连上设备并有上行音频,
   状态栏只出现**一次**「语音识别模型尚未就绪,暂不接收上行音频」。
2. **连续说话不丢段**(`issues/01`):连续说 3 段各约 3 秒的话,3 段都出现识别结果。
   若状态栏出现「识别速度跟不上,已丢弃最早的 N 秒音频」,说明这台手机转写比说话慢——
   这是如实上报,不是 bug,但请把出现的频率记下来。
3. **状态栏不再把进度显示成错误**(`issues/01`):正常使用时不应出现「Whisper 错误: 已接收…」,
   取而代之的是「已将 3.0 秒音频送入 Whisper」。
4. **断开后不串味**(`issues/02`):说话途中断开设备,重连后的第一条识别结果里不应带有
   断开前的内容;断开时正在转写的那一段也不应再产生回复。
5. **尾音冲刷**(`issues/02`):**仅对说完就停止上行的设备有意义**——说一句 1–2 秒的短指令后
   停止上行,约 0.6 秒后出现「已将 N 秒音频送入 Whisper」。接着仓库里的开发板固件时上行不会停
   (静音也照发),此条预期**不触发**,短指令在 3 秒窗口填满后被识别;请记录实际延迟。
6. **AI 请求超时与报错**(`issues/06`):
   - 把 API 地址指向一个不回包的端点,约 15 秒后状态栏出现「…请求超时,服务器长时间没有响应」
     (Ollama 这条路是 60 秒,见 `issues/06` 的 Answer);
   - 填错密钥,出现「服务端返回错误 HTTP 401: …」;
   - 断网或地址写错主机名,出现「连不上服务器: …」;
   - 清空某一项配置后发送,出现「尚未配置 … 接入」。
7. **回复排队**(`issues/08`):让两条回复重叠(第一条还在念时触发第二条),应当先念完
   第一条、再接着念第二条,中间不截断、不提前结束;开启回传时板子在两条之间不应停顿重启。
8. **选音频**(`issues/10`):选一个 16 kHz 单声道 16 位的 WAV,能识别且开头没有噪声;
   选一个 44.1 kHz 或立体声的 WAV,状态栏给出「仅支持 16 kHz 单声道 16 位 PCM 的 WAV,
   该文件为 …」并且不识别。
