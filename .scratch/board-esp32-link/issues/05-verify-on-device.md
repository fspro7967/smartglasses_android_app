# 05 — 开发板真机验收

Status: ready-for-human
Type: task

只能在真机上判。前置:固件已按 `issues/02` 抬高 MTU(否则第 3 条必然失败)。

## 前置

1. 烧录固件,打开串口监视器(115200),确认设备名 `ESP32_Audio`
2. 手机连上 `ESP32_Audio`,展开「蓝牙服务」
3. 若自动识别生效,状态行应显示「开发板: 扬声器(开启下方开关回传语音)」;
   特征列表里 `bebe…26a8` 不应能被设为输出(会被守卫拦回并提示)
4. 打开「语音回传眼镜」开关

## 判据

1. **上行**:对麦克风说一句英文,界面出现识别文本。
   若串口里 `mic:absent` 或没有音频包,是固件麦克风检测/接线问题,不是本仓库的问题。
2. **下行出声**:得到中文回复后,开发板功放应念出这句话,语速/音调正常。
   若听上去是半速慢放,说明 8k→16k 重采样没生效或走错了分支。
3. **不溢出**:完整听一遍 30 秒以上的长回复,状态栏不应出现
   「已停止蓝牙音频回传: 蓝牙吞吐不足…」。
   若出现,把串口/`adb logcat` 里 `DeviceHandler::writeData ... chunkSize =` 的值记下来
   —— 这是判断 MTU 是否生效的唯一直接证据。
4. **停止跟手**:按「停止」后板子立即安静,而不是把已入队的几秒播完。
5. **重播**:按「重播」应重新走一遍 `play` → 音频 → `stop`。
6. **本机静音**:回传期间手机扬声器不应出声。
7. **自动配置的诚实性**(对应 `issues/03`):确认状态栏说的和实际一致 ——
   例如把开发板音频特征的 CCCD 拿掉后重连,不应再出现「麦克风通知已开启」。

## 需要记录的数字

| 项 | 从哪里取 |
|---|---|
| 协商 MTU(chunkSize) | logcat 的 `DeviceHandler::writeData ... chunkSize =` |
| 30 秒回复是否溢出 | 状态栏 + logcat |
| 板子听感 | 正常 / 慢放 / 变调 / 断续 |
| 上行是否有丢包 | 串口 `audioCounter % 100` 日志与手机端识别结果对照 |

(或改成结论)。若固件需要改,改动记在 `smartglasses_board` 仓库,这里只留结论与链接。
